# Möbius–Kantor Closure Kernel

## Deterministic Incidence Closure Regime

### 1. Purpose

The Möbius–Kantor (MK) kernel is a deterministic closure regime for the (8₃) configuration: 8 points, 8 lines of 3 points each, forming the Möbius–Kantor graph. It defines how witnessed point ids and seed triples produce a closed incidence structure via deterministic closure rules.

### 2. Data Model

#### Point record

```
kind: "point"
id: "p:<hash>"
basisHash: "b:<hash>"
witness: ["cid:<hash>", ...]
tags: ["mk"]
meta: { labelHint: "optional" }
```

#### Block record (3-point "line")

```
kind: "block"
blockType: "line3"
points: ["p:<hash>", "p:<hash>", "p:<hash>"]
orientation: "+" | "-" | "null"
basisHash: "b:<hash>"
witness: ["cid:<hash>"]
ruleId: "mk.seed" | "mk.gen"
derivedFrom: []
```

- `orientation` ∈ {+, -, null} — participation vs quarantine
- `ruleId` — provenance anchor for determinism
- `basisHash` — canonical content hash for deduplication

### 3. Canonical Template

The MK configuration is generated by one seed line, e.g. `{0,1,3}` with indices mod 8:

```
Generator: L0 = {0, 1, 3}
Applied cyclically modulo 8:
  L0 = {0, 1, 3}
  L1 = {1, 2, 4}
  L2 = {2, 3, 5}
  L3 = {3, 4, 6}
  L4 = {4, 5, 7}
  L5 = {5, 6, 0}
  L6 = {6, 7, 1}
  L7 = {7, 0, 2}
```

This produces the full 8₃ configuration.

### 4. Closure Axioms

Given a set of points P and a set of blocks B (each a 3-subset of P):

**A1 — Identity:** `close(S) ⊇ S`

**A2 — Idempotence:** `close(close(S)) = close(S)`

**A3 — Monotonicity:** `S ⊆ T ⇒ close(S) ⊆ close(T)`

**A4 — Generation rule:** If a partial MK pattern is detected (a 3-line matching the template family), the remaining lines of the configuration are generated.

**A5 — Hash normalization:** Every block is canonically identified by `basisHash = hash(sorted(points) ++ orientation)`. If the same block already exists (by basisHash), it is not duplicated.

### 5. Orientation Rules

| State | Meaning |
|-------|---------|
| `+` | block is active / participating |
| `-` | block is quarantined / excluded |
| `null` | block is pending / undetermined |

Orientation is preserved through closure. A derived block inherits orientation from its generators.

### 6. Circuit Detection

Circuits are small minimal conflicts — subsets of blocks that form a cycle without completing the full configuration. The kernel detects:

- 3-cycles (triangles within the block graph)
- 4-cycles (quadrilaterals)
- small inconsistent orientation patterns

Circuits are recorded but do **not** prevent closure. They are surfaced for scoring/projection.

### 7. Deterministic Contract

```
Input:  S = (points P, seed blocks B_seed)
Output: S* = (P, B_seed ∪ B_derived) with circuits[] and drift/metrics
```

The computation is:

1. Normalize all inputs by basisHash
2. Detect MK template patterns in B_seed
3. Generate remaining lines of the 8₃ configuration
4. Deduplicate by basisHash
5. Detect circuits
6. Emit S*

### 8. Relationship to Fano Incidence

The MK configuration is an 8₃ incidence structure, distinct from the Fano plane (7₃). Both are:

- finite incidence geometries
- closed under deterministic generation rules
- usable as witness structures for OMI relation framing

Fano: 7 points, 7 lines, 3 points/line, every pair determines a line  
MK: 8 points, 8 lines, 3 points/line

The Fano plane is defined in `FanoIncidence02.v`. The MK kernel is a separate extension target.
